# Beats Your Music Design

## Goal

Build a localhost website named **Beats Your Music** that accepts a user-provided music file, estimates its BPM, defaults the target BPM to **180**, converts the track tempo to the requested BPM, and provides a downloadable converted file.

## Research Notes

- BPM means beats per minute: a numeric tempo count.
- Runner cadence is often discussed around 180 steps per minute because of Jack Daniels' elite-runner observations, but 180 is a practical default, not a universal ideal.
- Tempo conversion is `target BPM / source BPM`. A 150 BPM track converted to 180 BPM uses a `1.2x` tempo factor.
- Browser audio APIs can decode audio for analysis, but reliable encoded audio export is still better handled by FFmpeg on the server.
- FFmpeg `atempo` changes tempo and preserves pitch; factors outside the high-quality range should be chained.

## Product Shape

The app is a compact single-screen audio workstation, not a marketing landing page. The main workflow is:

1. Upload or drag a music file.
2. Analyze the file and show detected BPM, duration, type, and size.
3. Let the user correct source BPM, set target BPM, and choose half/double-time adjustment.
4. Convert to the target BPM.
5. Preview and download the output file.

## Architecture

- Vite React front end for the interactive UI.
- Express backend for upload, BPM analysis, tempo conversion, and download.
- `ffmpeg-static` supplies FFmpeg so the site works even when system FFmpeg is absent.
- `music-tempo` estimates tempo from decoded PCM data generated by FFmpeg.
- Server stores temporary upload/output files under `server/storage`, with best-effort cleanup.

## UI Direction

Use a dark graphite "running studio console" visual system with a disciplined lime accent and amber warnings. The memorable element is a horizontal tempo lane showing detected BPM on the left and target BPM on the right with beat ticks that visually compress or stretch.

## Main States

- Empty upload
- Drag-over upload
- Invalid file
- Analyzing
- BPM detected
- Manual source BPM correction
- Half/double-time source adjustment
- Large tempo-shift warning
- Converting
- Conversion complete with output preview and download
- Conversion failure with retry

## Error Handling

- Reject missing files, unsupported MIME families, invalid BPM values, and expired file IDs.
- Show inline errors, not only console logs.
- If BPM confidence is low or detection is missing, the user can enter source BPM manually.
- Warn when tempo scale is below `0.75x` or above `1.35x`.

## Testing

- Unit test tempo utility functions: tempo factor, BPM validation, FFmpeg `atempo` chain building, half/double adjustment.
- API smoke test with a generated click-track WAV to verify upload/analyze/convert/download.
- Production build check.
- Browser verification on localhost for upload UI, default 180 BPM, analyze state, conversion CTA state, responsive layout, and console errors.
